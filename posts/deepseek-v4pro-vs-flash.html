DeepSeek v4-pro 比 flash 贵 3 倍，但多花的钱买的不是「能力」

2026年10月13日 · 中文

我把同一个问题分别丢给 deepseek-flash 和 deepseek-v4-pro,相同的 thinking 开关,相同的 medium 推理档。

结果:答案质量没有区别,耗时差 2.2 倍,花费差 2.4 倍。

第二组实验更意外:v4-pro 开到 high 推理档,它把 6000 个 token 全部烧在思考过程里,一个字都没回答出来。

下面是我怎么测的、测出了什么、以及这个模型到底该怎么选。

先说一个大多数人都搞错的事:flash 才是新的那个

如果你跟我一样以为"pro 是高端、flash 是缩水版",版本时间线会让你意外:

deepseek-flash deepseek-v4-pro
实际身份 DeepSeek V4.1 Flash DeepSeek V4 Pro
发布 2026-09-10 2026-04-24
上下文 1,000,000 1,000,000
最大输出 384,000 384,000
输入模态 文字 + 图片 纯文字
reasoning ✓ ✓
tool call ✓ ✓

flash 比 pro 晚了四个半月。这不是"大杯和小杯",是两代东西被放在同一张价目表上。

顺带一个反常识:只有 flash 收图片。v4-pro 是纯文本模型。

价格:不是贵 3 倍,是贵 4.4 倍

官方 off-peak 单价(美元 / 百万 token),peak 时段翻倍,对应周一至周五 01:00–04:00 和 06:00–10:00 UTC:

输入 输出 cache 命中
deepseek-flash 0.15 0.60 0.003
deepseek-v4-pro 0.66 1.98 0.022
倍数 4.4× 3.3× 7.3×

先别急着看输入输出 —— 真正决定你账单的是最后那一列。

Agent 类应用(读写文件、调工具、多轮循环)的 token 绝大部分来自重复的上下文前缀,也就是 cache 命中那部分。这一项 pro 贵 7.3 倍。你的对话越长、跑得越久,实际成本就越靠近这个倍数,而不是靠近 3 倍。

实测:同一道题,两个模型

问题是一个老陷阱题:"农夫有 17 只羊,除了 9 只以外都跑了,然后卖掉剩下的一半,又买了 3 只 —— 现在多少只?这道题最容易踩的算术陷阱是什么?"

刻意选它,因为它考的是识别语言陷阱的能力,而不是计算量:

模型 / 推理档 耗时 思考 token 作答 token 花费
flash @ medium 18.1s 3898 77 $0.0024
flash @ high 14.2s 2953 77 $0.0018
v4-pro @ medium 39.0s 2837 69 $0.0058
v4-pro @ high 81.5s 6000 0 $0.0119

两个模型的答案实质相同:都算出 7.5 只(题目本身有小数陷阱),都准确指出了同一个陷阱 ——"all but 9 run away" 是"剩下 9 只",不是"跑了 9 只"。

v4-pro 输出了 69 个 token,flash 77 个,表达上 pro 更紧一点。但这不是值得付 2.4 倍价钱的能力差异。

真正值得说的一件事:v4-pro 在 high 档会把自己想死

最后一行是个真问题。81.5 秒,6000 个 token,全部消耗在隐藏的推理过程里,finish_reason 是 length,正文一个字都没有。

你付了 1.2 美分,拿到一个空回复。

这在 agent 场景里是很糟的失败模式 —— 不是报错,是静默失败。程序以为调用成功了,拿到空字符串,继续往下跑。如果你没在解析层做空内容检查,这个 bug 会以"模型偶尔抽风"的形式潜伏很久。

结论:v4-pro 不要配 high。 medium 就够,而且更省。

那 v4-pro 到底该什么时候用

我这四组数据不足以证明 pro 没价值 —— 一道陷阱题太简单,两个模型都能秒掉。按常识和定价结构,我的判断是:

用 flash 的场景(日常 90%): - 工具调用循环、文件读写、代码编辑 - 长上下文对话 - 任何需要图片输入的任务(pro 根本收不了) - 任何你会跑几十次以上的批量任务

切 v4-pro 的场景: - 难题:架构判断、复杂 debug、多步推理 - 一次性、你愿意为"想得更久"付钱的任务 - 推理档固定 medium

判据其实很简单:这次调用我跑几次? 一次 —— 用 pro。几十次 —— 用 flash,差价会变成你要不要交房租的问题。

方法说明与局限

我把方法和数据都摊开,包括对我自己不利的部分:

  • 每组只跑了一次。这个量级的耗时/花费差值里噪声很大 —— 注意 flash 的 high 档比 medium 档还便宜、还快,这纯属抖动,不代表 high 更省。想拿它当基准,至少要跑 10 次取中位数。
  • 单价我用的是本机内置的官方价格快照(快照日期 2026-09-10)。第三方目录 models.dev 给 v4-pro 报的是 0.435 / 0.87,和这个不一致。两处报价有出入,以你自己的账单为准。
  • 陷阱题只能测出"下限",测不出两个模型在难题上的差距。真想对比,得用 GPQA 之类的题集,那是另一个工程量。

附:两个实测出来的坑

既然都上台了,顺手说两个花了我时间才发现的东西。

一、deepseek-chat 和 deepseek-reasoner 已经死了,但你的配置不会报错。

DeepSeek 在 2026-07-24 下架了这两个 ID。它们现在不在 /models 列表里了,但接口并不拒绝它们 —— 实测发过去仍是 HTTP 200,服务端会换成 deepseek-flash 帮你跑完,只在响应体的 model 字段里留下痕迹。你的工具往往还会在更早的一层做同样的替换。

两层都不报错。你不会看到任何提示,只会以为自己一直在用某个更强的模型,实际跑的是 flash。

自查方法:别信配置文件,去看实际记录。最直接的是打印响应体里的 model 字段 —— 那是服务端确认的真相。如果你用 Hermes,记录在 ~/.hermes/state.db 的 session_model_usage 表里,那才是真正发出去的模型名。

二、把 provider 名当模型名用会 400。

deepseek 是服务商的名字,不是模型名。传进去会得到:

The supported API model names are deepseek-flash, deepseek-v4-pro, but you passed deepseek.

正确做法是定义别名(以 Hermes 为例):

hermes config set model.aliases.v4pro deepseek/deepseek-v4-pro

之后 /model v4pro 就能切换。

一句话总结: 贵的那 3 倍,买的不是更聪明的脑子,是更长的思考时间、更大的 cache 成本,以及一个在 high 档会当场想死机的失败模式。想清楚你要的是哪一个再掏钱。
